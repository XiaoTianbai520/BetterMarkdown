## 2. 产品定位与核心设计哲学

### 2.1 产品定位 (Product Positioning)
**ZeroMD Android 1.0** 是一款**纯粹、轻量、极致响应的 Android 专属本地 Markdown 编辑与知识记录工具**。
“Zero”象征着：
* **Zero Bloatware**（零功能膨胀，绝无多余工具链）
* **Zero Tracking**（零数据追踪，100% 隐私安全）
* **Zero Lock-in**（零格式绑架，纯文本开放标准）
* **Zero Distraction**（零界面干扰，即开即写）

它剔除了一切云端依赖、重型 AI 工具链和桌面级臃肿扩展，回归“工具即工具”的纯粹本质，专注于在移动端提供行云流水般的文本录入、阅读与文件组织体验。

### 2.2 核心设计哲学 (Design Philosophy)
1. **本地优先 (Local-First & Zero Lock-in)**：
   文档完全存放在用户自选的手机本地文件夹或存储空间中。不采用私有数据库包裹文档，100% 保持标准的 `.md` / `.txt` 纯文本存储，用户随时可自由迁移、备份。
2. **零膨胀 (Zero Bloatware)**：
   拒绝功能堆砌。不塞入多余的社交、商业计费、重型白板或云端推荐；包体积严格控制在极致水准，冷启动毫秒级响应。
3. **开箱即写 (Instant-On Flow)**：
   进入应用后无任何广告开屏、无登录强制弹窗，点击即可直接进入文档编辑状态，随手记录无需等待。
4. **原生触控手感 (Touch-First Craftsmanship)**：
   摆脱 Web 套壳常见的“钝感”与“浮动感”，针对移动端触控、软键盘弹起、手势交互和视口滚动进行深度打磨。

## 3. 严格边界与“不做什么”（Anti-Goals / Out of Scope）

> [!IMPORTANT]
> **本章节是防止项目未来功能蔓延（Scope Creep）的核心防火墙。以下内容在 1.0 乃至后续迭代中均严格禁止引入：**

1. **绝对不做自建云端账号与私有云同步服务**：
   不引入任何用户注册/登录、短信验证、自建服务器存储同步体系。用户如需跨端同步，依托第三方文件夹同步工具（如 Syncthing、FolderSync 等）基于本地目录自然协作。
2. **绝对不做重型 AI / Agent / MCP 体系**：
   不内置大模型调用、Agent 自动化执行流、本地向量数据库（RAG/SQLite 向量库）与本地大模型运行时。保持内存与电量零负担。
3. **绝对不做非文本类重型生产力套件**：
   不引入白板手绘引擎（如 tldraw/React 栈）、不引入幻灯片演讲模式（如 reveal.js）、不引入 Notion 式类数据库表格（Bases/公式系统）。
4. **绝对不做重型图表渲染引擎（如 Mermaid）**：
   剔除体积极大（数兆级）的 Mermaid 渲染器。所有代码块均按纯代码高亮呈现，保障极简与首屏渲染极速。
5. **绝对不做任何广告与商业支付插件**：
   彻底移除 Google Play Billing (IAP) 以及任何广告 SDK，保证应用 100% 纯净、安全。

| 角色 | 特征与痛点 | 1.0 典型使用场景 |
| :--- | :--- | :--- |
| **纯粹写作与随笔作者** | 需要随身记录灵感、日记、读书笔记；厌恶臃肿复杂的笔记 App 和登录限制。 | 在手机上打开 ZeroMD，秒开当前笔记库，利用底部软键盘快捷条快速输入标题、列表，纯粹沉浸输入。 |

## 6. 1.0 核心功能需求规格（Feature Matrix）

### 6.1 移动端 App Shell 与导航系统

```
+-------------------------------------------------------------+
| [☰ 抽屉]  当前文档标题.md          [👁 预览] [🔍 搜] [⋮ 更多] |  <- 触控顶栏 (52dp)
+-------------------------------------------------------------+
|                                                             |
|   # 沉浸编辑视口 (Editor.vue)                               |
|                                                             |
|   - 支持 GFM 语法                                           |
|   - 行内数学公式: $E = mc^2$                                |
|   - 触控流畅滚动，光标不被遮挡                              |
|                                                             |
+-------------------------------------------------------------+
|  [ B ] [ I ] [ H ] [ - ] [ 1. ] [ ` ] [ $ ] [ ↩ ] [ ↶ ] [ ↷] |  <- KeyboardBar (44dp)
+-------------------------------------------------------------+
|               Android 系统软键盘 (Keyboard)                  |
+-------------------------------------------------------------+
```

1. **触控顶栏 (Mobile Top Bar)**：
   - 高度标准为 `52dp`，符合 Material/触控工学规范。
   - **左侧**：抽屉唤出图标按钮（汉堡包图标），点击平滑滑出文件库抽屉。
   - **中部**：当前文档名称（超长自动省略截断，居中或左侧对齐）。
   - **右侧**：
     - **编辑/预览切换按钮**（笔/眼睛图标切换），支持一键在纯源码编辑与排版渲染视口间无缝切换。
     - **全局搜索按钮**：点击唤起搜索浮层。
     - **更多操作菜单**：弹出轻量操作菜单（打开库/新建笔记/文档统计/应用设置）。
2. **侧滑抽屉 (File Drawer)**：
   - 包含平滑遮罩（Scrim），支持从屏幕左侧向右轻扫（Swipe）手势滑出，点击遮罩或右划收起。
   - 抽屉顶部常驻：当前 Vault 目录名称、切换目录库按钮。
   - 抽屉主体：轻量文件树（`FileTree.vue`），支持多层文件夹折叠/展开、文档点击快速载入。
   - 抽屉底部：新建文档、新建文件夹操作入口。

### 6.2 工作区与存储模型 (Storage & Workspace)

1. **Vault 模式 (主存储模式)**：
   - 用户首次进入应用或点击“切换目录”时，通过 Android SAF（`ACTION_OPEN_DOCUMENT_TREE`）调起系统目录选择器，选择任意本地文件夹作为笔记库。
   - 应用获得持久化 URI 访问权限（`takePersistableUriPermission`），下次打开直接定位到该目录，无须重复授权。
   - 完全适配 Android 11+ 分区存储与各大 OEM（华为/荣耀/小米/OPPO/vivo）无权限弹窗报错。
2. **外部单文件打开模式 (Single-File Association)**：
   - 注册 Android `ACTION_VIEW` intent-filter，支持在任意第三方文件管理器或社交应用中将 `.md`, `.markdown`, `.txt` 文件“用 ZeroMD 打开”。
   - 单文件打开模式下，顶部显示独立文件名，支持实时修改保存并安全回写原 Uri。

### 6.3 极简编辑内核与键盘交互 (Editor & Keyboard Experience)

1. **CodeMirror 6 触控适配**：
   - 针对触控屏长按选区、拖拽光标把手（Cursor handle）进行平滑响应优化。
   - 默认开启软换行（Line Wrapping），避免移动端出现横向拉扯滚动条。
2. **软键盘吸顶辅助条 (`KeyboardBar.vue`)**：
   - 高度为 `44dp`，基于 `visualViewport` 精准定位，随键盘弹起/收起实现毫秒级吸顶贴合，杜绝浮空跳跃或延迟。
   - **核心格式按钮一键触达**：
     - `B` 粗体、`*` 斜体、`H` 标题循环（# -> ## -> ###）、`-` 无序列表、`1.` 有序列表、`[x]` 待办复选框、`code` 代码块、`$` KaTeX 公式、`Tab` 缩进、`Undo / Redo` 撤销/重做。
   - **不夺取焦点机制**：所有辅助条按钮点击事件采用 `event.preventDefault()`，保证点击按钮时软键盘不收起、光标焦点不丢失。

### 6.4 渲染与排版引擎 (Rendering Engine)

1. **语法支持规范**：
   - 严格遵循 **GitHub Flavored Markdown (GFM)** 规范：支持标题、强调、删除线、引用块、多级嵌套列表、GFM 表格。
   - **交互式任务列表 (Task Lists)**：在预览模式下，点击待办列表复选框可直接原地翻转 `[ ]` 与 `[x]` 状态并自动保存文件。
   - **数学公式 (KaTeX)**：完整支持行内公式 `$...$` 与独立块级公式 `$$...$$`，排版紧凑美观。
   - **代码语法高亮**：支持常用编程语言（JS/TS、Python、Rust、C/C++、Java、Go、JSON、YAML、Bash、SQL 等）的代码高亮。
2. **图表降级容错**：
   - 对历史文档中的 ````mermaid` 代码块，平滑退化为标准代码块展示，绝不引发页面崩溃或白屏。

### 6.5 本地化与通用设置 (Settings & Localization)

1. **设置面板精简版**：
   - **编辑器偏好**：字号大小滑块（14px - 24px）、行高倍率（1.4 - 2.0）、自动保存间隔（实时 / 1秒防抖 / 手动）。
   - **外观主题**：明亮主题 (Light)、暗色主题 (Dark)、自动跟随系统暗色模式。
   - **多语言**：简体中文 (zh-CN) 与 英文 (en-US)，默认跟随 Android 系统语言。
   - **关于**：版本号、开源协议说明与基础系统信息。

## 7. 非功能性指标与体验优化基准（NFR & Experience Standards）

> [!TIP]
> **后续所有针对本项目的体验优化工作，均必须以本章节制定的指标作为唯一验收基线：**

| 维度 | 1.0 目标指标 | 衡量方式 / 验收手段 |
| :--- | :--- | :--- |
| **安装包体积 (APK Size)** | **≤ 20 MB** (arm64-v8a 单架构) | `app-release.apk` 最终打包体积 |
| **冷启动首屏时间 (Cold Start)**| **≤ 500 ms** (中端及以上机型) | 从桌面点击图标到编辑器可接收文字输入的时间 |
| **内存占用 (RAM Usage)** | **常态 ≤ 90 MB**，编辑大文档 ≤ 140 MB | Android Profiler 监控稳定内存 |
| **触控输入延迟 (Input Latency)**| **≤ 16 ms** (保证 60/120Hz 满帧跟手) | 快速连续打字与长文本滑动无拖影与丢帧 |
| **光标防遮挡准确率** | **100% 不被软键盘遮挡** | 软键盘呼出时，光标自动平滑滚动至视口安全居中位置 |
| **触控热区安全度** | **所有按钮点击区域 ≥ 44×44 dp** | 边缘按钮具备足够的内边距，单手大拇指盲操零误触 |
| **数据安全性 (Zero-Loss)** | **崩溃/杀后台 0 数据丢失** | 采用 500ms 防抖自动落盘机制，退出前强制写入临时草稿 |

## 8. 后续体验感优化路线图（Roadmap for Experience Optimization）

作为 1.0 架构基线落地后的后续演进，体验优化将聚焦于**手机端细节质感的极致雕琢**：

1. **Sprint 1: 软键盘与光标微交互体验（Keyboard & Cursor Ergonomics）**
   - 彻底优化 Android 各种定制输入法（搜狗/微信输入法/Gboard）弹起时的视口平滑度，消除抖动。
   - 为底部辅助工具栏按钮加入符合 Android 规范的微触觉震动反馈（Haptic Vibration Feedback）。
   - 增加移动端常用双符号快速包裹体验（如选中文字点括号自动双边包裹）。
2. **Sprint 2: 移动手势与单手操作流（Gestures & Single-Hand Operation）**
   - 左右全屏轻扫手势切换前一篇/后一篇笔记。
   - 双指轻捏（Pinch-to-zoom）实时无级调节编辑器字号。
   - 底部下拉阻尼动画与弹性回弹效果优化。
3. **Sprint 3: 移动端中文排版美学与 OLED 适配（Typography & OLED Dark）**
   - 优化中文排版规范（标点挤压、中英文混排自动微空格呼吸感）。
   - 提供针对 OLED 屏幕的极致省电纯黑（Pure Black #000000）主题。
   - 针对平板与折叠屏设备的双栏自适应展示优化。
